# Архитектура

`AppCoordinator` открывает хранилище и создаёт граф зависимостей. `SceneDelegate` управляет окном. `WeatherRootViewController` отвечает за города, onboarding, UIPageViewController и маршруты; `WeatherViewController` — за состояние страницы, таблицу дней и горизонтальную UICollectionView часов. `ForecastDetailViewController` отображает часы и дневную детализацию. UI работает на MainActor.

`WeatherAPIClient` и `GeocodingService` используют асинхронный URLSession, ограничивают время запроса и проверяют HTTP-код. Декодирование/нормализация выполняется вне MainActor. DTO отделён от Codable/Sendable доменных моделей. Отсутствующие числа остаются nil и отображаются как «—». Параллельные массивы проверяются на совпадение длины до индексирования. Часы API запрашиваются как Unix timestamps, а форматирование выполняется с IANA timezone города, включая DST.

`WeatherRepository` — actor, связывающий сеть и Core Data. Для страницы выполняются последовательные стадии cached → refreshing → fresh/offline. Task отменяется при переключении страницы. Каждый запрос имеет идентификатор, поэтому завершение отменённой операции не обнулит новую. Состояние каждой страницы привязано к неизменяемому city.id; прогноз одного города не попадёт на экран другого.

`CoreDataStack` использует только private queue contexts и context.perform. `@unchecked Sendable` ограничен этой оболочкой контейнера; NSManagedObject и контексты не выходят за её методы. Модель WeatherModel v1 компилируется momc; managed-классы не генерируются. Включены automatic/lightweight migration. Проверено повторное открытие текущей схемы SQLite; миграция из несуществующей старой версии не заявляется.

Две сущности: CityRecord(id unique, position, Codable payload с названием/страной/координатами/timezone) и ForecastRecord(cityID unique, fetchedAt, Codable payload). Payload хранит весь current/hourly/daily snapshot, включая все поля детальных экранов. Это осознанный компромисс: простое атомарное чтение полного прогноза без запросов по отдельным погодным метрикам. Новая несовместимая версия Codable требует явного версионирования payload и миграции. Удаление города транзакционно удаляет его прогноз. Настройки/onboarding/выбранный город — UserDefaults.

LocationService создаёт CLLocationManager на MainActor; @preconcurrency-конформанс отражает доставку делегата по run loop создания менеджера. Разрешение запрашивается в первый раз после явного действия. При отказе ручной ввод доступен. Новая геопозиция фиксируется по запросу пользователя; постоянного отслеживания, фоновой геолокации и фонового обновления нет.

У приложения нет токенов. Сетевые адреса HTTPS, исключений ATS нет. PrivacyInfo описывает приблизительную геопозицию для функциональности и доступ к собственным UserDefaults. Для геокодинга Apple может выполнить reverse geocoding текущей геопозиции; ручные названия ищутся в Open-Meteo/GeoNames. Внешний учебный репозиторий Navigation не используется и не меняется.
